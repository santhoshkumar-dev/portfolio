## Introduction

Redis (Remote Dictionary Server) is an open-source, in-memory data structure store that has become one of the most popular databases worldwide. Known for its blazing-fast performance, Redis serves as a cache, message broker, streaming engine, and primary database for millions of applications.

This comprehensive guide will take you through Redis fundamentals, advanced features, and real-world patterns that power modern applications.

## What Makes Redis Special?

Redis stands out from traditional databases with several key characteristics:

- **In-Memory Storage**: All data resides in RAM for microsecond latency
- **Rich Data Structures**: Beyond simple key-value, supports lists, sets, hashes, and more
- **Atomic Operations**: All operations are atomic, enabling safe concurrent access
- **Persistence Options**: Optional disk persistence without sacrificing speed
- **Pub/Sub Messaging**: Built-in publish/subscribe capabilities
- **Lua Scripting**: Execute complex operations atomically
- **Replication & Clustering**: Built-in high availability and horizontal scaling

## Core Data Structures

Understanding Redis data structures is crucial for designing efficient solutions.

### 1. Strings

The most basic type, storing text or binary data up to 512MB.

```javascript
const redis = require("redis");
const client = redis.createClient();

await client.connect();

// Basic operations
await client.set("user:1000:name", "John Doe");
const name = await client.get("user:1000:name");

// Atomic increment
await client.set("page:views", "0");
await client.incr("page:views"); // Returns 1
await client.incrBy("page:views", 10); // Returns 11

// Expiration
await client.setEx("session:abc123", 3600, "user-data");

// Multiple operations
await client.mSet({
  "user:1000:email": "john@example.com",
  "user:1000:age": "30",
});
const values = await client.mGet(["user:1000:name", "user:1000:email"]);
```

### 2. Hashes

Perfect for representing objects with multiple fields.

```javascript
// Store user object as hash
await client.hSet("user:1000", {
  name: "John Doe",
  email: "john@example.com",
  age: "30",
  country: "USA",
});

// Get specific fields
const email = await client.hGet("user:1000", "email");

// Get all fields
const user = await client.hGetAll("user:1000");
console.log(user); // { name: 'John Doe', email: '...', ... }

// Increment numeric field
await client.hIncrBy("user:1000", "age", 1);

// Check if field exists
const exists = await client.hExists("user:1000", "phone");

// Get all field names
const fields = await client.hKeys("user:1000");
```

### 3. Lists

Ordered collections supporting push/pop from both ends (perfect for queues and stacks).

```javascript
// Queue implementation (FIFO)
await client.rPush("queue:tasks", "task-1");
await client.rPush("queue:tasks", "task-2");
const task = await client.lPop("queue:tasks"); // Returns 'task-1'

// Stack implementation (LIFO)
await client.rPush("stack:history", "page-1");
await client.rPush("stack:history", "page-2");
const lastPage = await client.rPop("stack:history"); // Returns 'page-2'

// Blocking operations (wait for data)
const item = await client.blPop("queue:tasks", 5); // Wait up to 5 seconds

// Range operations
await client.lRange("queue:tasks", 0, 9); // Get first 10 items
await client.lTrim("queue:tasks", 0, 99); // Keep only first 100

// Length
const length = await client.lLen("queue:tasks");
```

### 4. Sets

Unordered collections of unique strings, perfect for tags and membership testing.

```javascript
// Add members
await client.sAdd("user:1000:interests", ["coding", "gaming", "music"]);

// Check membership
const isMember = await client.sIsMember("user:1000:interests", "coding");

// Get all members
const interests = await client.sMembers("user:1000:interests");

// Set operations
await client.sAdd("user:2000:interests", ["gaming", "sports", "travel"]);

// Intersection (common interests)
const common = await client.sInter([
  "user:1000:interests",
  "user:2000:interests",
]);
// Returns ['gaming']

// Union (all interests)
const all = await client.sUnion(["user:1000:interests", "user:2000:interests"]);

// Difference (interests unique to user 1000)
const unique = await client.sDiff([
  "user:1000:interests",
  "user:2000:interests",
]);

// Random member (useful for sampling)
const random = await client.sRandMember("user:1000:interests");
```

### 5. Sorted Sets (ZSets)

Sets with an associated score for each member, automatically sorted by score.

```javascript
// Leaderboard implementation
await client.zAdd("leaderboard", [
  { score: 1000, value: "player1" },
  { score: 850, value: "player2" },
  { score: 1200, value: "player3" },
]);

// Get top players (highest scores)
const topPlayers = await client.zRange("leaderboard", 0, 2, { REV: true });
// Returns ['player3', 'player1', 'player2']

// Get top players with scores
const topWithScores = await client.zRangeWithScores("leaderboard", 0, 2, {
  REV: true,
});

// Get rank (0-based)
const rank = await client.zRevRank("leaderboard", "player1"); // Returns 1

// Get score
const score = await client.zScore("leaderboard", "player1");

// Increment score
await client.zIncrBy("leaderboard", 50, "player1");

// Get by score range
const midTier = await client.zRangeByScore("leaderboard", 800, 1100);

// Count by score range
const count = await client.zCount("leaderboard", 900, 1100);
```

## Caching Strategies

Redis is most commonly used as a cache. Here are proven patterns:

### 1. Cache-Aside (Lazy Loading)

Application checks cache first, loads from database on miss.

```javascript
async function getUser(userId) {
  const cacheKey = `user:${userId}`;

  // Try cache first
  const cached = await client.get(cacheKey);
  if (cached) {
    return JSON.parse(cached);
  }

  // Cache miss - load from database
  const user = await db.users.findById(userId);

  // Store in cache with TTL
  await client.setEx(cacheKey, 3600, JSON.stringify(user));

  return user;
}
```

### 2. Write-Through

Update cache and database simultaneously.

```javascript
async function updateUser(userId, updates) {
  const cacheKey = `user:${userId}`;

  // Update database
  const user = await db.users.update(userId, updates);

  // Update cache
  await client.setEx(cacheKey, 3600, JSON.stringify(user));

  return user;
}
```

## Persistence Options

Redis offers two persistence mechanisms:

### RDB (Redis Database)

Point-in-time snapshots at configured intervals.

- **Pros**: Compact, fast startup, good for backups
- **Cons**: Potential data loss between snapshots

```bash
# redis.conf
save 900 1      # Save if 1 key changed in 15 minutes
save 300 10     # Save if 10 keys changed in 5 minutes
save 60 10000   # Save if 10000 keys changed in 1 minute

dbfilename dump.rdb
dir /var/lib/redis
```

### AOF (Append-Only File)

Logs every write operation.

- **Pros**: Better durability, minimal data loss
- **Cons**: Larger files, slower startup

```bash
# redis.conf
appendonly yes
appendfilename "appendonly.aof"

# Sync strategies
appendfsync always    # Sync every write (slowest, safest)
# appendfsync everysec  # Sync every second (good compromise)
# appendfsync no        # Let OS decide (fastest, least safe)
```

## Real-World Use Cases

### 1. Session Management

```javascript
// Express.js session store
const session = require("express-session");
const RedisStore = require("connect-redis").default;

app.use(
  session({
    store: new RedisStore({ client }),
    secret: "your-secret-key",
    resave: false,
    saveUninitialized: false,
    cookie: { maxAge: 86400000 }, // 24 hours
  })
);
```

### 2. Rate Limiting

```javascript
async function rateLimit(userId, maxRequests = 100, windowSeconds = 60) {
  const key = `ratelimit:${userId}:${Math.floor(
    Date.now() / 1000 / windowSeconds
  )}`;

  const requests = await client.incr(key);

  if (requests === 1) {
    await client.expire(key, windowSeconds);
  }

  if (requests > maxRequests) {
    throw new Error("Rate limit exceeded");
  }

  return { remaining: maxRequests - requests };
}
```

### 3. Real-Time Analytics

```javascript
// Track daily active users
async function trackActiveUser(userId) {
  const today = new Date().toISOString().split("T")[0];
  const key = `dau:${today}`;
  await client.pfAdd(key, userId); // HyperLogLog for cardinality
  await client.expire(key, 86400 * 7); // Keep for 7 days
}

// Get count
async function getDailyActiveUsers(date) {
  const key = `dau:${date}`;
  return await client.pfCount(key);
}
```

## Best Practices

### 1. Key Naming Convention

Use hierarchical naming with colons:

- `user:1000:profile`
- `session:abc123`
- `cache:product:5000`

### 2. Set Expiration

Always set TTL to prevent memory bloat:

```javascript
// Good
await client.setEx("temp:data", 3600, value);

// Bad - never expires
await client.set("temp:data", value);
```

### 3. Use Pipelining

Batch multiple commands to reduce network round trips:

```javascript
// Inefficient - multiple round trips
for (let i = 0; i < 1000; i++) {
  await client.set(`key:${i}`, i);
}

// Efficient - pipelined
const pipeline = client.multi();
for (let i = 0; i < 1000; i++) {
  pipeline.set(`key:${i}`, i);
}
await pipeline.exec();
```
